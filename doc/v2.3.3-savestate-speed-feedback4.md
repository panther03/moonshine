# Savestate speed: feedback 4

The crowded third slot was spending time compressing the incoming state into
formats that still could not fit, then repeating those passes after shrinking a
retained state. The fixed pool remains 18,808,832 bytes. No state is evicted and
no reservation or archive format changes.

The save path now remembers complete candidate sizes within one save, skips
known sizes that still cannot fit, and tries shrinking retained quick states
before spending an incoming compact pass. The fast Deflate parser also indexes
one consumed match-tail trigram in its existing table. This costs about 2.2%
more fast-parser work on the checked PPC samples but can avoid a whole dense
pass. The shared bounded word-copy helper reduces compressed-output, pool-copy
and the fast parser's dictionary-fill work without changing compressed bytes.

## Controlled transaction measurements

These are private PAL Dolphin guest-time measurements using production codec,
CRC, replacement and repacking helpers on captured bytes. Codec and CRC used
the production O2 setting; save helpers used Oz. The final shared copy was the
same single 628-byte Oz body selected by the PAL release link. The clock is retail
OSGetTime. The benchmark does not run gameplay or rendering during the timed
operation, and disables interrupts before entering its private loop.

The transaction includes compression, retained-state decode/repacking, bank
commits, metadata tags and final packed CRC. It excludes game readiness,
snapshot capture, audio/cache lifecycle and return-to-game presentation. These
numbers are not complete visible save times and do not establish Wii targets.

| Capture set | Original third transaction | Revised policy/encoder | With shared copy |
| --- | ---: | ---: | ---: |
| Peaceful Plaza | 6.073 s | 2.205 s | 2.157 s |
| Bianco-plant Plaza | 6.100 s | 2.222 s | 2.173 s |
| User's current Plaza states | 10.537 s | 6.101 s | 6.006 s |

The final narrow change also replaces the fast parser's two disjoint
dictionary-fill copies with that same helper. Repeating the user's exact three
states improved its third transaction again, from **6.006 to 5.663 seconds**.
The final reduction from the original transaction is **46.3%**. First/second
quick transactions and every compressed hash were unchanged by this last step.

For the user's current states, the original candidate passes were two Quick,
two Fast and one Compact. The revised path used one Quick and two Fast, with
one retained Quick-to-Fast repack in both cases. The older Plaza sets instead
fit the slightly smaller fast candidate directly and avoid compact compression.
The user's first two quick transactions improved from approximately
0.565/0.583 seconds to 0.537/0.556 seconds with the shared copy helper.

After every save, every occupied slot was copied out and independently decoded
with a small LZ4 reference decoder or Python zlib. All decoded bytes matched the
original raw capture. Each packed CRC matched Python's CRC32, retained metadata
identity/sidecars stayed unchanged, and the shared-copy pass produced identical
compressed hashes to the preceding revised-policy pass. Each owned benchmark
process was stopped afterward; the user's separate process was never modified.

The isolated evidence is deliberately ignored under
`build/v2.3.3-feedback4/state-speed/`:

- `user-capture/capture.json`, `metadata.json`: read-only captures from the user's
  completed timing session, including exact regions and heap extent.
- `ppc-bench-results.json`: fast/compact parser work comparison. The user's
  emulator was still running for this earlier microbenchmark, so its host wall
  times are provisional; paired guest tick counts were exactly repeatable.
- `ppc-save-policy-results.json`: original versus revised transaction, three
  complete save sequences on both historical Plaza captures and the new user
  capture, with independent checks after each operation.
- `ppc-save-shared-results.json`: final shared-copy transaction and exact hashes.
- `ppc-save-final-results.json`: final dictionary-fill copy comparison on the
  user's exact three states. `shared-copy-identity.json` verifies the complete
  helper instruction bytes against the final PAL linked object.

The final dictionary-copy version passed all 50 focused codec, retained-state
repacking and recompression tests, covering dictionary wrapping, split spans,
short buffers, malformed streams, capacity failures, and retained identities.
The broader 118-test savestate suite passed before that last copy-only change;
the parent build performs its full final checks separately.

The user separately measured the unmodified feedback-3 build in normal Dolphin:
Save 1 0.600 s, Load 1 0.500 s, Save 2 0.634 s, Load 2 0.467 s, Save 3 10.511 s,
Load 3 0.901 s. Saves were timed from timer freeze to unfreeze; loads from timer
freeze to Mario's first visible frame. Their earlier Wii baseline was saves 1/2
0.567 s, loads 1/2 0.367 s, save 3 6.674 s and load 3 0.568 s.

## Remaining tradeoff

The fresh user's first two quick streams occupy 13,686,424 bytes. Their improved
fast third stream needs another 5,809,345 bytes: 686,937 bytes more than the fixed
pool can hold. At least one retained stream must therefore become smaller in
this case. The checked safe path validates and stages its replacement while
keeping the old stream intact. There is no basis for promising every third save
under two seconds with this fixed memory map. More reserved pool space, a
different compressor, or a larger design change that prepares states outside
the save operation would involve separate tradeoffs; none was silently added.
