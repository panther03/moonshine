# V2.3.3 RAM restore speed audit

The `v1.0-rc3` implementation kept one uncompressed state. Its restore copied
32-bit words from MEM2 into game memory and stored the resulting cache lines.
The current three-state pool adds compression, a packed-stream CRC check, raw
Adler validation and retained-owner/recording policies. Both versions already
used the graphics completion barrier and `DCStoreRange`. The old implementation
is therefore a useful latency reference, but does substantially less work.

## Checked direct Quick blocks

Quick/LZ4 restore previously decoded every block through the 128 KiB MEM2
workspace whenever a copy policy was present. Most ordinary RAM heap blocks
need no filtering, so that wrote and reread their entire uncompressed contents
before copying them into MEM1.

`decompressVerified` now accepts an optional direct-write permission callback.
Only a compressed block with its complete checked raw length inside one output
span can request permission. Ordinary RAM restoration grants it only when:

- The state has no durable/imported owner profile.
- No restore bindings are being preserved.
- The entire destination is within the captured stage heap.
- The block does not intersect the current live-video allocation.

All other blocks use the existing copy policy. Static spans, TAS/ghost sidecars,
durable/SD restores and every protected intersection keep their previous
behavior. Plain Quick blocks and Deflate decoding also keep that behavior.

The saved packed CRC is still rechecked with interrupts disabled before the
verified decoder is entered. Source/destination/descriptor checks, framing,
bounded LZ4 decoding, exact decoded length and final Adler remain in place. An
unexpected verified-pass failure still produces `COMMIT_FAILED`; the RAM caller
traps instead of resuming a partially restored game.

There are no new allocations, reservations or file-format changes. An isolated
PAL object comparison measured 200 additional initialized bytes for direct
output: 72 in the codec and 128 in the savestate helper/call site.

## Shared filtered copy

Sunshine's retail `memcpy` (`Runtime/__mem.c` in the decompilation) copies bytes
one at a time. The final non-durable copy now reuses `StateSlotPoolCopyForward`,
the existing bounded pool-copy helper. It uses alias-safe aligned word accesses,
handles unaligned sources without reading outside their spans, and retains
exact byte edges. Durable owner copies retain their previous implementation.
This occurs inside `copyBaseStateBytes`, after the existing video/binding/TAS
filters, and does not widen any write or bypass an exclusion. The compressed
output sink shares the same helper as well.

Sharing the already-linked helper removed the separate 100-byte copy-loop
addition from the first candidate. Data/BSS and memory reservations remain
unchanged. Final regional link sizes remain authoritative.

## Measured scope

The private PAL Dolphin test used the user's captured slot 2 Quick stream,
including its real game-region lengths. The output regions were mapped into a
separate contiguous MEM1 test destination; the recording tail was grouped and
there was no live THP allocation in this fixture. Interrupts were disabled and
no gameplay or rendering ran during the measurement. All restored bytes were
compared with the captured raw state after each decode.

These are **emulator guest timings**, not Wii memory-bus measurements or complete
button-to-visible-frame load times. Three repetitions produced identical guest
tick counts.

| Operation | Guest time |
| --- | ---: |
| Quick decode through existing copy policy | 317.49 ms |
| Quick decode with checked direct heap blocks | 195.58 ms |
| Quick decode with direct blocks and shared remaining copies | 193.13 ms |
| Packed CRC of the 6,862,467-byte stream | 60.03 ms |
| Raw Adler over 15,178,256 bytes | 97.82 ms |
| Original-style aligned word copy | 31.23 ms |
| `DCStoreRange` over the same destination | 6.83 ms |

The combined decode improvement is **39.2%** in this fixture. Direct output removes the scratch copy
for 14,811,136 of 15,178,256 raw bytes; 367,120 bytes retain the filtered path.
Adler time is already included in both decode rows and must not be added again.

The user's retained dense slot 1 and slot 3 streams took 747.87 and 750.74 ms to
decode through the original Deflate copy path, plus approximately 51 ms each for
packed CRC. Shared filtered copying reduced those decode times to **646.47 ms**
and **649.22 ms**, respectively. Quick direct output does not apply to Deflate;
its parser, history ring and checksum logic remain unchanged.

Evidence is under `build/v2.3.3-feedback4/load-audit/`: `direct-bench-results.json`,
the exact `ppc-direct-bench.cpp`/ELF/binary, `direct-size.json` and
`direct-source-receipt.json`. The final combined comparison is recorded in
`shared-bench-results.json`, `ppc-shared-bench` artifacts and
`shared-source-receipt.json`. `shared-copy-identity.json` proves that the test's
628-byte helper matches the actual PAL savestate object's entire function body,
compiled with its `-Oz` options, byte for byte. The earlier `word-*` receipts
describe the superseded local-copy candidate. All private Dolphin processes
were stopped afterward.

## Verification

The 92 focused codec/archive/streaming/live-video/checkpoint and pool/bank tests passed,
including direct blocks around retained bytes, split and zero-sized spans,
plain/Deflate fallback, malformed framing before permission, and valid framing
with malformed LZ4 that reports fatal commit failure while retaining buffer
guards. The production permission helper is tested for JP/US/PAL with heap
edges, out-of-heap spans, integer-sized overrun attempts, video intersections,
durable profiles and captured bindings. A separate review found no blocking
ownership or validation issue.

The shared-copy tests cover every combination of source and destination byte
alignment, zero/tiny/large lengths, random contents, exact tails, unchanged
sources, surrounding guards and protected fragments at aligned and unaligned
boundaries on JP, US and PAL helper builds.

No ordinary QFT source, settings, state metadata or checksum semantics changed.
