This is local test work, not a published release.

## Corrected behavior

- A manual restart accepted during streaking death no longer waits for the
  retail death animation. The ordinary result, CARD and protected-PB guards
  remain in place; automatic retries still wait for the retail death tail.
  Private PAL Ricco 4 Reds testing measured state 7 to 9 below 0.1 s after the
  restart chord versus about 4.36 s before. It retained the same IL and counted
  one failed attempt. A no-input control still took about 4.31 s.
- Fast Text supplies its short literal at the audited fallback text-parser
  call. It no longer writes into hardcoded message-buffer addresses or guesses
  PAL's language. Original JP/US/PAL call sites were checked against disc data;
  an actual PAL parser call passed Off / On / Off without changing message
  bytes or entry attributes. This was a direct parser fixture, not an NPC run.
- Ghost lighting and reconstructed FLUDD animation are described separately
  in `v2.3.3-ghost-lighting-animation.md`.
- Single Ghost Watch recognizes retail ledge-hanging animations in its
  existing real-floor-contact predicate. No matching recorded ledge hang was
  supplied for natural runtime verification; racing and two-ghost Watch keep
  their prior behavior.

## Performance changes and limits

- ISO cache fills are sector aligned and consume an existing cached prefix
  before fetching the missing suffix. The actual PAL DVD trace requires
  1,725 device requests versus 2,210, with identical bytes. This is not a Wii
  elapsed-time result. It affects ISO reads, not launcher storage scanning.
- State-save retries retain measured compression sizes within the current
  save, avoiding repeated modes already proved too large after repacking.
  Fast retained-state repacking precedes the incoming dense pass. The fast
  encoder indexes the final consumed trigram of a match, improving density
  without a new table or format. Dense fallbacks and safe refusal remain.
- Codec output, fast Deflate dictionary fills and ordinary filtered restores
  share the existing bounded word-copy helper instead of retail byte copies.
  C++ callers share one linker body. Checked Quick heap blocks can also decode
  directly into their destination, retaining the original policy around live
  video, model bindings, durable owners and recording data. Details and the
  exact decoder measurements are in `v2.3.3-state-restore-speed.md`.
- On the three user-captured states, the complete isolated save transaction
  measured 10.537 to 5.663 guest seconds for slot 3. Slot 1 measured 0.565 to
  0.537 seconds, and slot 2 measured 0.583 to 0.556 seconds. The benchmark
  includes compression, retained repacking, pool commits and packed CRC;
  it excludes game readiness, capture and surrounding graphics/audio work.
  All streams decode to their original bytes and retained identities survive.
  These are Dolphin instruction timings, not confirmed Wii targets.
- Unused miniz convenience APIs now occupy separate linker sections. The
  linker can discard them without changing compressor/decompressor logic.
  No memory reservation or state capacity is enlarged.

No measured Wii target is claimed as achieved. The requested sub-two-second
third save remains open; final console tests must also measure loads after
retained slots have been repacked.

## QFT audit

`src/qft_timer.cpp` remains exactly the protected source blob
`c31dda5ddc9d5b1a0cfc3fd985f8d907fa4f5890`. No timer code was edited.
The millisecond conversion is integer `qf * 1001 / 120`, consistent with
30000/1001 rendered frames per second and four QFs per rendered frame.
It truncates rather than rounds milliseconds: at eight QFs, for example,
66.733… ms displays as 0.066, while nearest-millisecond rounding gives 0.067.
This can explain a 0.001 difference against a video tool, but the actual
reported discrepancy remains unconfirmed without its start/end frame pair.
