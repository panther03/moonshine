# V2.3.3 follow-up: checked savestate load speed

This follows the verified restore changes in `v2.3.3-state-restore-speed.md`.
The user measured the preceding Wii build at 0.334 seconds for ordinary Plaza
loads and 0.500 seconds for slot 3. Those hardware measurements remain distinct
from the private emulator timings below.

## Adopted changes

- CRC retains its existing four-byte step. Its tables and running value use
  native word order on PowerPC, avoiding a byte swap for every input word. The
  public unfinished seed and result retain the existing reflected CRC format.
- The CRC borrows the same 4 KiB of the existing idle codec workspace.
  The caller already owns the complete workspace exclusively and reinitializes
  these tables after any codec operation. No reservation or file format grows.
- Adler processes 64 bytes using aligned words and four independent byte sums.
  Each pair of sums occupies two 16-bit integer lanes. Across sixteen words,
  each lane sum is at most 4,080 and each sum of partial sums is at most 34,680;
  carries cannot cross lanes. The weighted result is algebraically identical
  to the original byte recurrence. The 5,552-byte modulo bound, exact byte
  prefix/tail, null-input behavior and external seed semantics remain intact.
- Quick and Deflate share that Adler routine rather than keeping a second
  copy inside the inflater. Existing bounded inflater copies share the already
  linked forward-copy helper. Deflate match decoding itself is unchanged.

Every compressed byte still participates in the CRC before a RAM restore.
Every decoded byte still participates in Adler. Corrupt-stream handling,
output-length checks, retained owner/video filters, publication, recovery and
interrupt ownership are unchanged. No QFT code is changed.

## Isolated measurements

Each row used the same actual user-captured packed state and output spans in
a private PAL Dolphin game-thread fixture. The fixture disables interrupts
and rendering, compares the complete result with the independently captured
raw bytes, and repeats each case three times. Guest ticks were identical
across repeats. These are emulator instruction timings, not Wii timings or
complete button-to-visible-frame latency.

| Capture | Operation | Before | After |
| --- | --- | ---: | ---: |
| Slot 2, Quick | CRC including table initialization | 60.026 ms | 56.496 ms |
| Slot 2, Quick | Decode, integrity and retained-copy policy | 193.127 ms | 170.682 ms |
| Slot 1, Deflate | CRC including table initialization | 50.922 ms | 47.928 ms |
| Slot 1, Deflate | Decode, integrity and retained-copy policy | 646.472 ms | 625.792 ms |
| Slot 3, Deflate | CRC including table initialization | 51.305 ms | 48.289 ms |
| Slot 3, Deflate | Decode, integrity and retained-copy policy | 649.215 ms | 628.498 ms |

Separate profiling of the preceding complete load found no meaningful extra
guard to remove: the queued load already starts in the same frame, and the
second GX barrier took about 0.005 ms. That barrier remains. Cache publication
and interrupt/audio resumption also remain.

General long-match copies, aligned match copies and repeated-byte Deflate
branches were tested privately and rejected because they slowed the real
captures. Larger scalar Adler unrolling was less effective than the adopted
arithmetic. None of those rejected decoder branches enters production.
An eight-byte CRC variant saved another 5.3 ms on the Quick capture but cost
268 more linked instruction bytes than the adopted CRC4 routine. The smaller
variant keeps all three regional builds within the unchanged staging limit.

## Verification and evidence

102 focused codec, checksum, restore, archive, video, streaming and pool tests
passed. Coverage includes an independent zlib comparison for 8,520 Adler
vectors, all alignments, worst-case bytes, arbitrary seeds, modulo boundaries
and fragmented input. CRC tests run both the host arithmetic and the PowerPC
big-endian arithmetic with only native loads emulated, including all four
tables, tails, fragmented spans, guard bytes and rejected workspace bounds.
Existing malformed/corrupt codec and protected-output tests remain enabled.

The complete production `mz_adler32` and CRC `update` instruction bytes match
their measured private candidates exactly. Receipts are in
`build/v2.3.3-feedback5/load-speed/`:

- `final-candidates-bench-results.json`: final Adler comparisons and exact bytes.
- `round2-bench-results.json`: CRC comparisons and exact checksum results.
- `final-source-receipt.json`: source/input hashes, function identity, focused
  test scope and object sizes.

The codec object grows 12 initialized bytes and the CRC object shrinks 120 bytes;
neither adds static data or BSS. Regional linked size checks determine final
package fit. The separate complete-load measurement uses the final build.
