# Savestate lifecycle profiling, feedback 5

The complete load path was measured before changing any readiness checks or
graphics barriers. No lifecycle guard was removed: the useful cost is in the
packed checksum and decoder, which are optimized separately.

## Scope

The baseline is the verified feedback-4 PAL Dolphin image under
`build/v2.3.3-feedback4/bps-final`, corresponding to source commit
`f3930288d9517ab3c24157708b891259bb581ead`. The private fixture replaces selected
call instructions with timestamp wrappers. Those wrappers forward the original
arguments, stack arguments, return value and condition register, and call each
original target exactly once. They do not replace the algorithm or bypass its
checks. Their bounded code and timestamp log occupy the unused end of the
existing mod span only in that fixture; production reservations are unchanged.

The fixture starts Gelato Enter into PAL Plaza, then uses ordinary Left saves
and queued Right loads. Times below use retail `OSGetTime` on the emulated CPU.
They include instrumentation overhead and are **not Wii timings**, nor the
elapsed time until the next image is physically visible. In particular, they
must not be described as the earlier codec-only 0.193-second result.

## Complete baseline

| Operation | Complete function | Main components |
| --- | ---: | --- |
| Save 1 | 529.52 ms | Quick compression 459.16; pool commit 10.91; packed CRC 58.23 |
| Save 2 | 529.20 ms | Quick compression 458.54; pool commit 10.91; packed CRC 58.21 |
| Load 1 before third save | 254.12 ms | Packed CRC 58.23; decode/copy 187.94; cache store 6.76 |
| Load 2 before third save | 254.41 ms | Packed CRC 58.21; decode/copy 187.94; cache store 6.76 |
| Save 3 | 5,445.23 ms | Incoming Quick/Fast trials, one retained repack, Fast retry and commits |
| Load 1 after third save | 689.25 ms | Packed CRC 49.25; Deflate decode/copy 631.52; cache store 6.76 |
| Load 2 after third save | 254.66 ms | Packed CRC 58.21; Quick decode/copy 187.94; cache store 6.76 |
| Load 3 | 689.40 ms | Packed CRC 49.24; Deflate decode/copy 631.60; cache store 6.76 |

The third save repacks slot 1 in this scene, so it is important to distinguish
loading the first two states before saving the third from loading all states
afterward. Final retained streams were Deflate/Quick/Deflate, respectively
5,629,559 / 6,655,081 / 5,628,861 bytes. All three compressed CRCs were checked and
their streams were independently decoded after the sequence. All three slots
remained present. These captures are useful controlled examples, not predictions
of the user's hardware times or every Plaza state.

An initial three-repeat Quick-load profile measured 254.67 ms with less than
0.03 ms spread. Its request-to-load-entry delay was 0.115 ms, within the same
frame. The second `GXDrawDone` call cost 0.0047 ms in Dolphin. Readiness,
metadata validation, sound and feature reconciliation were small: metadata
validation was about 0.143 ms per occupied slot, and interrupt resumption about
1 ms. There was no fixed extra frame wait to remove. Actual Wii GX latency is
not established by this emulator measurement.

Ordinary loads retain the completed retail render barrier and the direct-call
barrier. They wait across frames only when CARD is actually busy. Scene, heap,
owner, live-video and packed-integrity checks remain intact. The measured
fixed save work was similarly small outside compression, pool copying and CRC.

## Final full-function profile

The final PAL image, CRC32 `E06FED31`, was measured with refreshed symbols and
the same scripted save/load sequence. This is a second fresh Plaza session,
not a replay of the identical captured bytes. The separate `load-speed`
experiment supplies the exact-same-capture checksum/decoder comparison.

| Complete operation | Baseline session | Final session |
| --- | ---: | ---: |
| Load 1 before third save, Quick | 254.12 ms | 227.68 ms |
| Load 2 before third save, Quick | 254.41 ms | 228.07 ms |
| Load 3, Deflate | 689.40 ms | 663.06 ms |
| Save 1 | 529.52 ms | 500.19 ms |
| Save 2 | 529.20 ms | 515.82 ms |

The approximately 26 ms reduction in the representative complete loads is
consistent with the separately measured checksum/Adler improvement. It is not
a new Wii timing result or proof of any requested visible-load threshold.

The final third save took 1,990.01 ms, but **that is not a measured improvement
over the baseline third save**: its slightly different scene bytes fit without
repacking a retained slot. Its final slots were Quick/Quick/Deflate at
6,594,101 / 6,597,591 / 5,572,787 bytes. The baseline needed a retained repack
and ended Deflate/Quick/Deflate. All three final streams independently decoded
to their complete expected raw lengths, their packed CRCs matched, and loads
of every slot succeeded after saving slot 3. Slot 1's different final load
cost is therefore also not attributed to the checksum changes.

After profiling, the same owned fixture started a real Ricco 4 Reds streak
and received retail X+B+Start (`0x1600`) through its raw controller source.
Intro Skip was On. The retail reset flag rose, the application returned to
context 4, and the active streak became inactive there. No reset flag or
application-context value was written by the test. The owned Dolphin process
was then stopped. This verifies that actual reset path, not every possible
controller configuration or hardware reset mechanism.

## Rejected larger-table experiment

The production encoder already overrides LZ4's default memory usage of 14 with
15, using a 32 KiB table. PPC type-size checks give:

| LZ4 memory usage | Quick workspace | Fits current workspace |
| --- | ---: | --- |
| 14 | 279,092 bytes | Yes |
| 15, current | 295,476 bytes | Yes |
| 16, 128 KiB blocks | 328,244 bytes | No |

The existing work object is 319,296 bytes inside the fixed 319,488-byte
reservation. A private usage-16/120-KiB-block encoder fits at 311,828 bytes,
but native-host screening of twelve real captures saved only about 63–90 KiB
per state. For the user's first two captures the total fell by 166,063 bytes;
even using that host result, adding the known Fast third stream still exceeded
the pool by 376,751 bytes. It did not avoid the retained repack. Host table/hash
selection differs from PPC, so these are screening results, not PPC ratios.
No production block format, table, workspace or reader was changed.
