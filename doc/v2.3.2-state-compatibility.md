# Savestate compatibility correction

The public V2.3.1 and V2.3.2 releases share snapshot 17, but SD admission used
the complete mod-file CRC as its compatibility identity. This correction admits
their six exact regional identities and writes the stable restore-contract ID
`0x4D530011` for new archives. A future change to restore layout or semantics
must change that contract. Unknown builds and other snapshot versions remain
unsupported.

The archive header and owner profile must still agree on their original build
and configuration. Both profile checksums are validated; comparison ignores
only the compatible build identity and its derived checksum. All other bytes,
including owner anchors, allocation ranges and padding, must match. Region,
episode, snapshot spans, checksums and storage receipts retain their checks.

Old states contain mod addresses in live Mario/FLUDD packet callbacks and the
player-group node holding GhostView. Before durable restoration, collect those
typed fields from the current initialized models and group. Skip only their
four-byte words when restoring, alongside the existing owner/video filters.
Reject before writing if those live bindings cannot be checked. Clear transient
player drawing queues after restoration so an old submission cannot survive.
There is no general pointer scan or substitution based on integer values.

Streaming keeps the original candidate metadata unchanged for receipt checks
and recovery. Export normalizes a separate metadata copy and recomputes its
checksums. Saving a legacy TAS creates a new project and exports all components
under the stable identity; an unsuccessful save preserves the original project.
Memory reservations, compressed pool capacity, snapshot layout and QFT timing
are unchanged.

Evidence belongs to `build/v2.3.2-state-compat`. A real public V2.3.1 PAL SD
archive was decoded read-only to verify the old typed pointers. The runtime
fixture uses a public V2.3.1 US emulator image with byte-identical mod spans and
a private SD-service adapter; its emulator-specific identity is admitted only
in the private test build. This does not establish Wii or Wii U verification.
