# V2.2.0 PPC loader optimization audit

## Scope

`SUSAMUNE_LOADER_OPTIMIZATION` selects `-Os` (the default) or `-O3` for the
libogc launcher target only.  The root build forwards the cache value through
the launcher super-build to its `wii` group.  It is deliberately absent from
the `ppc` and `arm` groups: the ARM kernel remains `-O2`, and the injected game
mod keeps its own toolchain flags.

This is a size/boot-memory trade, not a gameplay optimization.  FreeType,
libpng, zlib, libmad, libogc, and fatfs-ppc are prebuilt or separate targets and
do not inherit this switch.

## Controlled comparison

The comparison used devkitPPC r35 / GCC 8.3.0 and minimal FreeType enabled.
Both builds read the same frozen source tree and the exact same generated
kernel, PPC helper, build-id, and fatfs archive bytes.  `SOURCE_DATE_EPOCH` was
fixed at `1787248800` because the launcher displays `__DATE__`/`__TIME__`.
Repeating both clean builds produced the same `boot.dol` hashes.

The independent ELF-to-DOL verifier retained the same ten sections.  It found
20 bytes of alignment padding for `-O3` and none for `-Os`.  Both ELFs are
big-endian PowerPC executables with entry point `0x80004000`, five load
segments, and no remaining relocations.

ABI/layout checks:

- Every `-O3` global symbol remains present with `-Os`.  The 81 extra `-Os`
  symbols are outlined functions and standard libgcc register save/restore
  helpers that `-O3` had inlined.
- All 149 global data symbols retain their type and size.
- All 75 global BSS/SBSS symbols keep the same relative layout; the complete
  block only moves down by the reclaimed 35,008 bytes.
- The only dynamic stack report remains an unused GRRLIB bitmap effect; its
  static part falls from 96 to 88 bytes.  The largest per-function stack
  increase is 128 bytes, leaving that function at 136 bytes.
- Both modes emitted the same warnings in the frozen comparison; none was
  optimization-specific.

## Verification and remaining gate

The complete current host suite passes 284/284 tests, including focused
launcher CRC, IPL, MEM2-ownership, path, font, and heap-lifetime contracts.
Invalid cache values fail configuration; `-O3` remains the documented escape
hatch.

Before calling the default hardware-cleared, smoke both Wii and vWii:

1. Start the HBC app and exercise the progressive-mode prompt and every main
   launcher menu page with both GameCube and supported Wii-family input.
2. Check stock rendering, a custom JP theme, TrueType text, MP3 playback, and
   the update/status screen preservation path.
3. Mount SD and USB independently and together; scan a disc and an ISO, write
   configuration, and exercise the network update error/success paths.
4. Boot JP, US, and PAL Sunshine through the kernel handoff, open the mod menu,
   enter a stage, then return and repeat after launcher music has shut down.
5. Compare conspicuously slow scans, hashes, downloads, or UI stalls against an
   `-O3` override build.  Any material regression is sufficient to switch that
   build back without changing the ARM kernel or game mod.
